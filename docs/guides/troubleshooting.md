# Troubleshooting

Symptom, likely cause, fix. These are derived from the code and the starter's documentation, not from
incidents on a real account.

## Terraform and CI

| Symptom                                                                | Cause                                                                         | Fix                                                                                   |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Plan fails with `stage and prod need domain_name`                      | The domain rule in `app-stack`                                                | Set `domain_name` and `hosted_zone_id`, or use `dev`                                  |
| `Backend initialization required`                                      | The backend has no bucket yet                                                 | `terraform init -backend-config="bucket=<bucket>" -backend-config="region=<region>"`  |
| `Error acquiring the state lock`                                       | Another run holds the S3 lock object, or a crash left it                      | Wait; if sure nothing is running, `terraform force-unlock <id>`                       |
| `Ephemeral outputs are not allowed in context of a root module`        | Running `validate` or `test` directly on `modules/secrets`                    | Use `./scripts/check.sh`; the module is tested through `tests/harness`                |
| Deploy: `starter_ref must be a full 40-character commit SHA`           | A branch or tag was entered                                                   | Use `git ls-remote https://github.com/sotream/nest-next-starter main`                 |
| Deploy cannot assume the role                                          | The job is not in the GitHub Environment, or `AWS_DEPLOY_ROLE_ARN` is missing | Check the Environment name matches `dev`, `stage` or `prod` and has the variable      |
| Plan comment missing on a pull request                                 | Fork, or `AWS_PLAN_ROLE_ARN` or `TF_STATE_BUCKET` unset                       | The workflow prints a notice and skips by design                                      |
| Recreating an environment fails with a secret "scheduled for deletion" | 7-day recovery window                                                         | `aws secretsmanager delete-secret --secret-id <name> --force-delete-without-recovery` |
| `terraform destroy` stops on ECR repositories                          | They still hold images                                                        | Empty them ([operations](operations.md#destroy-an-environment))                       |

## Tasks and the application

| Symptom                                                               | Cause                                                                                                                                                                                                                                                      | Fix                                                                                                                                    |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Tasks stop with `CannotPullContainerError`                            | No path to ECR: NAT missing, or the image tag does not exist                                                                                                                                                                                               | Check the NAT gateway and route tables; confirm the tag in ECR                                                                         |
| Tasks stop with `ResourceInitializationError ... secret`              | The execution role cannot read the secret, or the NAT is down                                                                                                                                                                                              | Check the secret ARNs in the execution role policy and the NAT                                                                         |
| API exits at start with `Invalid environment configuration`           | The starter's validation. In prod mode it says `JWT_ACCESS_SECRET must be a non-default value of at least 32 characters`, `WEB_ORIGIN must be an https origin`, `DATABASE_URL must not use the default credentials` or `REDIS_URL must include a password` | Read the task's log group; check the three secrets exist and have values, and that a domain is set for `APP_ENV=prod`                  |
| Targets unhealthy, ALB returns 503                                    | Security group, wrong health path, or the API cannot reach the database or Redis (`ready` fails)                                                                                                                                                           | Check the target group health reason; task security group ingress from the ALB; `/api/health/ready` in the task logs                   |
| API tasks keep restarting during a database or Redis outage           | The target group checks `/api/health/ready` and ECS replaces tasks the load balancer reports unhealthy                                                                                                                                                     | Set `api_health_path = "/api/health/live"` ([architecture overview](../architecture/overview.md#request-flow))                         |
| Healthy tasks, but users are signed out on every reload               | Origin mismatch: the web image was built with a different `NEXT_PUBLIC_API_URL` than `WEB_ORIGIN`, or the cookie is `Secure` on HTTP                                                                                                                       | Use the deploy workflow (it builds with the public origin); never serve `APP_ENV=prod` over HTTP. This is the starter's same-site rule |
| Sign-in returns `429` for everybody                                   | Rate limits are shared behind the ALB ([ADR 0006](../adr/0006-trust-proxy-behind-alb.md))                                                                                                                                                                  | Wait a minute; lasting fix needs `TRUST_PROXY` in the starter                                                                          |
| API logs show Redis `WRONGPASS` or `NOAUTH`                           | The AUTH token in `REDIS_URL` does not match the cache                                                                                                                                                                                                     | Rotate with a new `CREDENTIALS_VERSION` and restart (`force_restart`)                                                                  |
| API logs show a database `password authentication failed`             | Credentials rotated but tasks not restarted, or the URL secret and the instance diverged                                                                                                                                                                   | Run the deploy with `force_restart`; if it persists, raise `CREDENTIALS_VERSION` again                                                 |
| API logs show a TLS error to the database (`self-signed certificate`) | `sslmode` in `DATABASE_URL` is `verify-full` or `require` without the RDS CA in the image                                                                                                                                                                  | Keep `db_ssl_mode = "no-verify"` ([ADR 0008](../adr/0008-database-tls.md))                                                             |
| `no pg_hba.conf entry`                                                | The client did not use TLS while `rds.force_ssl = 1`                                                                                                                                                                                                       | The `DATABASE_URL` must end in `?sslmode=no-verify`                                                                                    |
| Migration task exits non-zero                                         | A failing migration, or the database is not reachable                                                                                                                                                                                                      | Read `/nnat-<env>/migrate`; fix the migration; the deploy leaves services untouched                                                    |
